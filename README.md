# PAX Tracker

An unofficial PAX Unplugged booth planner. React + Vite serves the frontend on Vercel; Supabase Auth and Postgres provide email sign-in and private cross-device progress. The original HTML export provides an optional starter shortlist, not an official directory. Verify booth numbers and availability before using it on the show floor.

## Set up the backend

1. Use separate Supabase projects for preview and production. The GitHub Actions workflow applies committed files in `supabase/migrations/` to Preview for same-repository pull requests, then to Preview and Production after changes are pushed to `main`. The database enforces account ownership on both tables, including the parent booth for each game.
2. In Authentication, enable the Email provider and **Allow new users to sign up**. New users create an account using the same email-code flow as returning users. The app uses email codes rather than passwords.
3. Configure [custom SMTP](https://supabase.com/docs/guides/auth/auth-smtp) first; hosted Supabase requires it to edit email templates. Then go to **Authentication > Email Templates > Magic Link or OTP**, set the subject to `Your PAX Tracker sign-in code`, and paste [the email template](supabase/templates/magic-link-or-otp.html) into the body. Keep `{{ .Token }}` intact: Supabase replaces it with the one-time code.
4. Copy `.env.example` to `.env.local` and use the preview project's URL and **publishable** key. Only these public values belong in Vite environment variables; never use a service-role key or an SMTP credential there.

## Run and deploy

- Local: use Node.js 22, run `npm ci` and `npm run dev`. `npm run build` type-checks and builds the site.
- Local UI preview without sign-in: run `VITE_LOCAL_PREVIEW=true npm run dev -- --host 127.0.0.1`. Preview data stays in this browser's local storage and never connects to Supabase; it is separate from your account. This mode works only in the Vite development server on localhost and is disabled in production builds.
- Database: run `supabase/tests/isolation.sql` against a development Supabase database after applying the migration. It checks account isolation and rolls back its test data.
- Migration deployment: create GitHub environments named `supabase-preview` and `supabase-production`. Add `SUPABASE_ACCESS_TOKEN` and `SUPABASE_DB_PASSWORD` as environment secrets and `SUPABASE_PROJECT_ID` as an environment variable in each. Configure required reviewers on `supabase-production` if production migrations should wait for approval. Before the first automated deploy, link each project with the Supabase CLI and mark only migrations whose SQL is already present in that database as applied using `supabase migration repair <timestamp> --status applied --remote`; otherwise `db push` may try to recreate existing objects. Since `20261124090000_import_games_to_try.sql` was applied manually, mark version `20261124090000` as applied in both projects before enabling the workflow. Pull requests from this repository that change migrations deploy to the shared Preview project; fork pull requests do not receive environment secrets or deploy migrations. Preview changes persist if a pull request is closed or its migration changes, and concurrent pull requests may conflict or leave remote migration history ahead of `main`. Reconcile the preview schema and migration history before further deployments if this happens; never repair history without also checking the schema. For isolated per-PR databases, use Supabase Branching and configure each preview app to use its branch credentials. On pushes to `main`, migrations deploy to Preview first, then Production. The workflow can also be run manually from GitHub Actions on `main`.
- Vercel: set `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` for **Preview** and **Production** using the corresponding Supabase project. Push the branch or redeploy after changing variables; Vite reads them at build time.
- Before merging, sign in with an approved test user on two devices or browser profiles. Load the shortlist, mark a booth visited on one, and refresh the other. Then try a second account and confirm it starts with an empty list.

Checklist data is stored in Supabase; the browser stores the auth session and device-local map settings. The **Refresh** button fetches changes made on another device. **Export list** downloads a human-readable snapshot; it is not an import or restore format. Offline edits are not supported.

**Update booths** loads the public 2026 PAX Unplugged exhibitor directory on demand. Search by exhibitor or booth number, then import a stop or explicitly update a matching booth number without changing your progress. If the directory is offline, you can still add a booth manually.

**Collection** accepts the original BoardGameGeek **Collection → Download board games → all** CSV. The complete CSV, including every row, column, and personal comment, is stored with your private account so future features can use it; the app also saves selected fields for its current features. Existing collections must be re-imported once to preserve fields that were previously discarded. Replacing a saved collection shows the incoming count and sample titles for confirmation before replacing both the parsed data and CSV. Removing the collection deletes both but does not remove saved booth stops. Apply the latest migration before importing collections. Game-title matches use the official PAX Games & Goods listings, while publisher matches use the full expo exhibitor directory. Exact listed games rank ahead of publisher-only matches; within each match type, suggestions prioritize wanted games, then ratings of 8 or higher, then owned games. **Import owned-game booths** adds matching booths for owned games without replacing existing stops. **Refresh suggestions** reloads the saved collection and current PAX listings; upload a new CSV to incorporate changes made on BGG. The listings are partial, so no match does not mean a game won't be at the show.

**Map & route** is a prototype covering booths in Halls A and B from the [official 2026 expo map](https://unplugged.paxsite.com/philly/en-us/info/maps.html). Tap a booth to see its exhibitor from the official directory, or search by booth number or exhibitor to find and zoom to it. Choose all unvisited, all, or selected checklist booths and start at a mapped booth or the approximate Queue entrance near booth 1821; the starting booth list can also be searched. Route settings and the active stop stay on this browser, separately for each account, and do not sync between devices. Select a route stop or use the previous/next controls to find it on the map; these controls do not mark booths visited. For exhibitors with multiple booth numbers, choose one mapped location; other locations are not included in the route. Unmapped, unresolved and duplicate booth numbers are listed separately. Additional exhibits in other rooms are listed for reference, but are not mapped or included in routes. Routes follow manually mapped aisles and use a nearest-stop heuristic; they are approximate and do not account for crowds or changed floor layouts. Check the official map and on-site signs.

**Games** keeps separate Games to Try and Games to Buy lists with manual additions and checkboxes. Each list shows 10 games per page with its own navigation. Importing BGG want-to-play or want-to-buy games adds missing titles to the corresponding list without removing existing entries. Re-import older collections from a CSV containing the `wanttoplay` and `wanttobuy` columns to enable these imports. Find booths for each game using PAX game listings and publisher matches from your saved BGG collection. You can view matching booths on the map or add them to your checklist and device-local route; existing route stops are retained. The expo listings and map are incomplete, so matches and route locations should be verified. Apply the latest migration before using these lists.

**Game Library** shows games marked want-to-play in your saved BGG collection, sorted by BGG community average when available. It displays the BGG score from `average` (out of 10) and community complexity from `avgweight` (out of 5). Games without scores sort alphabetically after scored games. Collections saved with their full CSV use these columns automatically; older collections need a re-import. Box art is not currently available.
